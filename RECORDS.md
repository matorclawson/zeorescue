# Automatic recovery records

Recovery metadata is generated by software during normal operation. No seat,
Codex/Claude invocation, model call, mailbox, Runtime API or manually written
manifest is involved. The org chart remains the desired-state source; this is a
local derived recovery cache, not a second configuration system.

## What runs automatically

After the reviewed implementation is installed on the Mac, the operator runs
`make records-install` once. It installs a user launchd job named
`ac.zeo.rescue-records`. The job performs a finite `records.sh capture` every 30
seconds and at login. It does not run a resident agent, start targets or repair
anything. Installation refuses an existing job/plist rather than replacing it.
`make records-service` only generates the plist for inspection.

The collector may disappear with the login session. That is fine: previously
written records remain on disk and are used during recovery. The job resumes at
login. Recovery does not require the collector to be alive.

`make records` performs the same finite capture manually or from another program.
The recovery script also attempts it after launches. Normal seat lifecycle code
should call the capture command immediately after creating/changing a session,
when the native session identity is observable. This reduces the polling window;
it is an ordinary program call, not an instruction to an AI seat.

No service was installed by this council. The generated job refers to the reviewed
checkout's absolute path; install from its permanent location after integration.
It uses the current rodbot user's normal HOME and does not request credentials.

## Sources and saved facts

The collector joins the org chart with the actual tmux pane, harness process,
process cwd/identity and native history. It can identify a native session from an
exact resume-process UUID or an unambiguous open native-history file. Open files
are validated against native metadata before they are trusted. A newer file in a
directory is never a selection criterion.

Each saved row records seat/mailbox, harness, exact native session ID, working
directory, tmux session, pane marker, policy/launch arguments, native-history path,
observation timestamp and evidence source. It does not store prompts, command
lines, credentials or full environments. Process environment inspection is used
only to check the identity and is not persisted.

Codex reads use `mode=ro`, never `immutable=1`, and require exact ID AND cwd. The
rollout's session metadata must agree. Claude uses the exact native transcript
and checks its session/cwd metadata. Policies come from structured native events;
text embedded in a message is not treated as a policy declaration. Lookup examines
the last 5000 complete JSONL lines, and fails if supported policy cannot be found.
The full observed policy object is retained, but the existing launch adapter still
supports only its documented approval/sandbox or permission-mode flags: qualification
of additional policy fields remains required before using those histories.

The pane marker is observed, including `inactive`. A missing marker is an issue,
not permission to invent `master`. A known shared-daemon Codex launch is not accepted
as a valid observation for this recovery path. A row is evidence of a mapping,
not proof that every tool or external integration is healthy.

## Storage and failures

Default files:

- `~/.local/state/zeo-rescue/recovery-records.json`: current generated cache.
- The `.previous` sibling: previous complete cache for forensic comparison; never
  automatically substituted for a corrupt current cache.
- `ORG-CHART.last-good.json`: automatically retained chart, available after upstream
  services disappear.

The collector uses a single-writer directory lock, private file creation, a temporary
file and atomic rename. A killed capture cannot expose a partially written current
JSON file. This is atomic replacement, not a guarantee against every power-loss or
filesystem failure; maintain normal host backups. Stale locks are reported and
require inspection instead of unsafe automatic removal.

When a seat is down, its last complete row is retained, including its original
observation timestamp. A fresh conflicting identity, marker, mapping or ambiguous
thread blocks use of that seat's saved row. A later healthy observation clears the
conflict. Duplicate native sessions block the observed set. Invalid chart/process
inspection does not overwrite the previous cache. Capture returns 0 for a complete
usable collection, 3 for per-seat issues and 1 for collection/storage failure.

`ZEO_RESCUE_RECORDS` selects another cache path. Existing chart/history/tool overrides
apply; `ZEO_RESCUE_HOST` and `ZEO_RESCUE_SOCKET` select the observation host label and
tmux socket. Both AI rescuer launch paths carry these same explicit settings.

## During an outage

`make plan` uses the saved mapping and re-reads the policy from that exact native
history. It validates the mapping against the current or cached org chart. Session
pins and `--session` may assert the expected identity but cannot override the cache.
`--before` is refused: timestamp-based snapshot selection no longer exists.

Normal `make rescue` leaves live sessions alone, checks for surviving native-session
processes/history holders, and resumes only recorded dead seats. It has no stop-seat
or daemon-stop phase. Both Claude transcripts and Codex rollouts receive holder
checks. Unresolved seats are named; independent recorded dead seats can still recover.
Each newly launched seat receives the existing basic environment proof, including
inactive policy. The rescue flag is `starting` until that proof passes, then `1`.
This still does not implement exclusive writer locks or a full external-action
quarantine; the earlier broader safety findings must not be treated as closed.

Live-seat repair remains explicitly `--reseat` and operator-controlled. It is not
part of ordinary crash recovery, and the old hash-pinned reseat commands remain
invalid for this changed implementation.

## Coverage limits to understand

A collector can record only observable facts. This implementation supports the
packet's tmux topology and visible native resume IDs, plus directly open, unambiguous
native histories. A wrapper process, a history held only by an untracked child, a
new session without visible native identity, or an in-UI thread switch whose identity
is not exposed can remain unresolved or leave the last sampled mapping stale.
The 30-second interval is not an event-complete lifecycle ledger. The normal launcher
should trigger capture after session changes; integrating another repository's
launcher requires that repository and has not been claimed here.

If the machine failed before the first valid capture, there is no truthful way to
invent the lost mapping. The operator gets the missing seat names; no harness is
asked to guess or maintain a manifest. Native history and external effects are not
made transactional by storing these recovery records.

## Validation

`make test` runs offline rescuer, records/recovery and guard suites. These include
actual script entrypoints with fake tmux/process/harness observations, a real SQLite
WAL fixture, complete outages, newer unrelated transcripts, missing upstream charts,
wrong identities, missing markers, corrupt caches, duplicate IDs and cleanup guards.
Real Mac process formats, launchd installation, native history variants, the shell
loader and both actual harness resumes still require host qualification.
